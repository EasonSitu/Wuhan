# Codex 交接说明：武汉两天半城市导览网页

## 项目目标

把当前单页 HTML 继续完善并部署成一个可分享的网站。网站不是普通“武汉旅游攻略”，而是面向用户这次真实行程的城市导览：

- 6/26 午夜到武汉
- 6/27 完整自由日
- 6/28 完整自由日，晚上入住光谷希尔顿
- 6/29 下午参加徐福记喜礼发布会
- 6/30 中午返程

核心定位：

> 武汉不是景点城市，要按江、街、早饭和三镇来读。

网站需要帮助用户快速理解武汉的城市渊源、三镇历史、风土人情、吃喝路线、行程拆解和手信选择。

## 当前文件

- `index.html`：当前完整单页网页，已包含正文、样式、交互、外链图片。
- `image_sources.md`：当前图片 URL 与 alt 文案清单。
- `reference_links.md`：当前资料/地图/官网入口清单。
- `codex_tasks.md`：推荐给 Codex 的下一步任务。
- `content_brief.md`：内容结构与语气要求。

## 重要设计原则

1. **不要继续用 AI 生成图作为主图。**  
   用户担心 AI 图片虽然漂亮但容易信息不准确。后续图片应优先使用网上真实图片、官方图片、Wikimedia Commons、政府/博物馆/景区官网图片。

2. **不要依赖远程图片外链。**  
   当前版本使用外链图，浏览器环境可能拦截，导致图片空白。后续应由 Codex 将确认可用且授权合适的图片下载到本地 `assets/images/`，压缩后以本地相对路径引用。

3. **资料入口不要太显眼。**  
   页面主体应该是讲解内容；资料、预约、地图、官网入口只用淡色小链接、折叠 details 或页面底部资料墙呈现。

4. **内容不要做成普通景点清单。**  
   重点是：城市渊源、三镇性格、历史建筑背后的故事、风土人情体验、按真实行程拆解。

5. **兼顾手机阅读。**  
   这是出行前/旅途中会打开的页面，所以移动端排版、图片加载、跳转导航要好用。

## 技术建议

当前是单文件 HTML。Codex 可以按两种方向继续：

### 轻量方向

保持静态站：

```text
index.html
assets/
  images/
  css/
  js/
```

适合直接部署到 Netlify、Vercel、GitHub Pages。

### 工程化方向

改成 Vite + React 或 Astro：

```text
src/
  components/
  data/
  pages/
public/
  images/
```

但项目不复杂，优先建议轻量静态站，避免过度工程化。

## 部署建议

优先 Netlify：

1. 创建新站点
2. 选择从 GitHub repo 部署，或直接拖拽包含 `index.html` 的文件夹
3. Build command 留空
4. Publish directory 设为项目根目录或 `dist`
5. 自定义域名可后续再加

也可以部署到 GitHub Pages：

1. repo 放 `index.html`
2. Settings → Pages
3. Source 选择 `main` branch root
4. 等待生成链接

## 需要 Codex 注意

- 不要把未经核验的网红店、播放量视频当成事实来源。
- 历史信息优先用地方志、博物馆、政府官网、文旅官网。
- 开放时间、预约政策、轮渡班次要加“以当天官方信息为准”。
- 美食推荐要避免写死某一家店，更多按街区和菜品类型推荐。
- 图片需保留来源记录，最好在 `image_sources.md` 里列出原始 URL、作者、许可或来源页面。
